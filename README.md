# 基于 S7-1200 的汽车电动车窗控制系统

> 车辆工程专业自学项目 · TIA Portal V16 · S7-1200 + PLCSIM 仿真验证

一个用于学习**车身电控逻辑设计与验证**的小项目：用西门子 S7-1200 实现车窗的上升、下降、互锁、限位、防夹与故障锁存，并在 S7-PLCSIM 中完成逐条测试。

项目重点不在"把功能做出来"，而在**把逻辑验证清楚**：每一段程序都有对应的测试用例，每一次修改都有前后对比记录。

## 3. 控制逻辑

### 程序结构（7 段）

| 段号 | 名称 | 作用 |
|---|---|---|
| 1 | 防夹确认 | 防夹信号持续 0.3 s 才认定 |
| 2 | 故障置位 | 确认后锁存故障 |
| 3 | 回弹计时 | 故障锁存后计时 0.8 s |
| 4 | 车窗上升 | 上升自锁 + 互锁 + 限位 + 故障封锁 |
| 5 | 车窗下降 | 下降自锁 + 互锁 + 限位 + 故障封锁 + 回弹支路 |
| 6 | 报警输出 | 故障 → 报警 |
| 7 | 故障复位 | 人工复位清除故障 |

### 逻辑表达式

```
段1：TON "DB_防夹确认"  IN := I0.4 ∧ (Q0.0 ∨ Q0.1)   PT := 300 ms
段2："DB_防夹确认".Q                    → (S) M0.2
段3：TON "DB_回弹"      IN := M0.2                    PT := 800 ms
段4：(I0.0 ∨ Q0.0) ∧ ¬I0.1 ∧ ¬I0.2 ∧ ¬M0.2            → Q0.0
段5：[(I0.1 ∨ Q0.1) ∧ ¬I0.0 ∧ ¬I0.3 ∧ ¬M0.2] ∨ [M0.2 ∧ ¬"DB_回弹".Q]  → Q0.1
段6：M0.2                                             → Q0.2
段7：I0.5                                             → (R) M0.2
```

### 三个设计要点

**① 自锁支路的位置**

自锁触点 `Q0.0` 并联在启动按钮 `I0.0` 两端，限位串在自锁环**之后**。
这样无论电机是刚启动还是处于自锁保持状态，限位一动作，回路必然断开。

**② 防夹只在运行时判断，且需持续 300 ms**

段 1 的条件带有 `(Q0.0 ∨ Q0.1)`，静止时的传感器信号不参与判断；
再经 TON 滤波，短于 300 ms 的毛刺不触发停机，避免颠簸或振动造成误动作。

**③ 回弹用故障位直接计时，不用边沿触发**

`M0.2` 一旦锁存就保持为 1，用它驱动 TON，前 0.8 s 内 `Q=0`、回弹支路导通；
`Q` 变为 1 后支路断开，回弹结束。因为 `M0.2` 不会自己复位，定时器只跑一次，不会反复回弹。

## 4. 版本演进

| 版本 | 内容 | 解决的问题 |
|---|---|---|
| **v1** | 3 段：上升、下降、报警。无中间变量，防夹直接串在回路里 | — |
| **v2** | 5 段：新增 `M0.2` 故障锁存 + 置位/复位段；报警改由故障位驱动 | 防夹释放后电机自动恢复 |
| **v3** | 7 段：防夹加 300 ms 确认（TON）；故障锁存后反向回弹 800 ms | 毛刺误触发；夹住后不松脱 |

### v1 → v2 的核心改动

v1 中防夹只是"串在回路里的一个常闭触点"：

- 防夹来了 → 回路断开
- 防夹走了 → 回路重新闭合，**电机自动接着上升**

这在实车上是危险的：夹到物体 → 松开 → 继续夹，反复动作。

v2 引入故障锁存：防夹触发后置位 `M0.2`，只有人工按复位才能清除，期间所有输出被封锁。

### v2 → v3 的核心改动

**防夹确认**：v2 只要防夹信号有效就立刻停机，传感器一抖就误报警。
v3 在信号与故障位之间加了一个 TON：信号必须连续保持 300 ms 才算数。

**反向回弹**：v2 夹住后只是停住，物体仍被夹着。
v3 在锁存故障后反向下降 0.8 s，模拟真实车窗的"松脱"动作，然后停止并保持报警。

## 5. 已实现的安全机制

- **自锁**：松开按钮后保持运行
- **互锁**：上升与下降互斥，同时按下不动作
- **到位停止**：上/下限位切断对应方向输出
- **防夹滤波**：防夹信号持续 300 ms 才认定为有效，滤除抖动
- **故障锁存**：故障状态保持，需人工复位
- **反向回弹**：确认防夹后自动反向下降 0.8 s 再停止
- **复位后可恢复**：排除故障并按复位后，可重新操作

## 9. 自动化回归

手工测试每轮约 40 分钟。`automation/` 用 Python 脚本替代手工操作：

```bash
cd automation
python run.py                          # 本地模拟器
python run.py --backend plc --ip <IP>  # 真实 PLC（S7 协议）
```

12 条用例自动下发激励、断言输出、记录耗时，单轮回归约 **5 秒**，输出 `reports/report.md` 与 JUnit 格式结果。

框架把 PLC 客户端抽象为可替换接口，模拟器与真实设备共用同一套用例。

详见 **[automation/README.md](automation/README.md)**。
