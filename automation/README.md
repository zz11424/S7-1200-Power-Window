# 车窗控制自动化测试框架

用脚本替代手工操作：自动下发输入激励、轮询输出、断言结果、记录耗时并生成测试报告。

同一套用例可运行在**本地模拟器**或**真实 S7-1200**上。

---

## 1. 背景

手工测试车窗程序的做法是：在监控表里改值 → 盯输出 → 记结果 → 截图。

问题有三个：

- 每轮回归约 40 分钟，且容易漏测
- 响应时间靠肉眼判断，0.3 s 与 0.8 s 分不清
- 结果只存在于截图里，无法比对两次回归的差异

本项目把上述过程脚本化，单轮回归压缩到 **5 秒**，并输出结构化报告。

---

## 2. 被测对象

本仓库根目录的 S7-1200 车窗控制程序（v3 版本，7 个程序段）。

| 输入 | 地址 | 含义 |
|---|---|---|
| up | I0.0 | 上升按钮 |
| down | I0.1 | 下降按钮 |
| limit_top | I0.2 | 上限位 |
| limit_bottom | I0.3 | 下限位 |
| pinch | I0.4 | 防夹信号 |
| reset | I0.5 | 报警复位 |

| 输出 | 地址 | 含义 |
|---|---|---|
| motor_up | Q0.0 | 电机正转 |
| motor_down | Q0.1 | 电机反转 |
| alarm | Q0.2 | 报警 |

约束条件：

- 上升与下降互锁
- 防夹信号需持续 300 ms 才认定为有效
- 防夹确认后反向回弹 800 ms
- 故障锁存，需复位才能恢复

---

## 3. 架构

```
run.py
  └─ runner.py        执行用例、断言、生成报告
       ├─ cases.py    用例表（12 条）
       └─ client.py   PlcClient 协议
            ├─ SimPlc      本地模拟器（默认）
            └─ Snap7Plc    真实 PLC（S7 协议）
```

`PlcClient` 只定义两个方法：`write_inputs()` 与 `read_outputs()`。
换后端不需要改任何用例。

**为什么要有模拟器**：

- 无硬件时也能跑，便于纳入 CI
- 修改用例或断言逻辑时，先用模拟器快速验证，再上真机
- 模拟器按 10 ms 步长推进，逻辑与 v3 梯形图一致

---

## 4. 用例设计

共 12 条，覆盖功能、互锁、时间参数与故障恢复四类。

| 编号 | 场景 | 关键断言 |
|---|---|---|
| TC-01 | 上升启动 | up=1 → motor_up=1（200 ms 内） |
| TC-02 | 上限位停止 | limit_top=1 → motor_up=0 |
| TC-03 | 自锁保持 | 松开 up 后 motor_up 仍为 1 |
| TC-04 | 上升下降互锁 | 同时按下，两路输出均为 0 |
| TC-05 | 防夹短脉冲 | pinch 持续 200 ms，alarm 不触发 |
| TC-06 | 防夹确认 | pinch 持续 > 300 ms，alarm=1 且 motor_up=0 |
| TC-07 | 反向回弹 | 确认后 motor_down=1 |
| TC-08 | 故障锁存 | 撤除 pinch 后再给 up，motor_up 仍为 0 |
| TC-09 | 复位清除 | reset=1 → alarm=0 |
| TC-10 | 复位后恢复 | 复位后可再次上升 |
| TC-11 | 下降启动 | down=1 → motor_down=1 |
| TC-12 | 下限位停止 | limit_bottom=1 → motor_down=0 |

### 用例间复位

每条用例执行前，框架会将全部输入置 0 并给一次复位脉冲。

**不做这一步，上一个用例遗留的故障锁存会让后续用例全部失败。**
这是自动化测试里最典型的"用例间状态污染"，也是本项目调试过程中实际踩到的坑。

---

## 5. 执行

```bash
python run.py                              # 本地模拟器
python run.py --backend plc --ip 192.168.0.1   # 真实 PLC
```

输出：

- `reports/report.md`：可读报告
- `reports/junit.xml`：JUnit 格式，可被 CI 直接消费

退出码：全部通过为 0，存在失败为 1。

---

## 6. 执行结果

```
后端：本地模拟器（SimPlc）
用例：12　通过：12　失败：0
总耗时：4.6 s
```

单条用例耗时 0.02–1.33 s，主要开销来自时间参数类用例的等待（防夹 300 ms、回弹 800 ms）。
相对手工回归的 40 分钟，单轮耗时降低约 99%。

报告见 [`reports/report.md`](reports/report.md)。

## 7. 接入真实 PLC

1. `pip install python-snap7`
2. TIA 中打开 CPU 属性 → 防护与安全 → 连接机制 → 勾选「允许来自远程伙伴的 PUT/GET 通信访问」
3. 下载硬件组态，确保 PC 与 PLC 同网段（PLCSIM 使用虚拟网卡，地址为组态中的 IP）
4. 执行 `python run.py --backend plc --ip <PLC_IP>`

**注意**：真实硬件上 I 区会被扫描周期刷新，直接写 I 区可能不生效。
稳妥做法是在程序中把 I 区映射到 M 区，测试框架改读写 M 区。

---

## 8. 局限与后续

- 模拟器与真实 PLC 的实现细节可能存在偏差，最终结论以真机为准。
- 当前为单设备串行执行，未做并发与数据驱动（同一用例多组参数）。
- 断言以布尔量为主，尚未覆盖位置、电流等模拟量。
- 后续可接入 Allure 报告、失败自动截图、与 CI 联动。
